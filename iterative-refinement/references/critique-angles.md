# 分领域对抗性审查清单

Phase 3 时先确定任务领域（可多个），逐项质问自己的产出。每项要求给出"通过 / 不通过 / 不适用"及理由；不通过项进入修改清单。

## 通用（所有任务必查）

1. 目标偏离：产出是否真的回答了原始问题，还是答非所问、只完成了容易的部分？
2.  weakest link：整个产出中证据最薄弱、最依赖假设的是哪一处？如果它错了，结论是否崩塌？
3. 未验证断言：是否存在没有实测、没有来源支撑就写下的断言？
4. 沉默的失败：有没有检查过但失败、却被悄悄绕过的项目？
5. 边界与异常：空输入、极端值、罕见情形是否会导致结果错误？
6. 验证成色：每条"已验证"结论的验证手段属于哪一级（A 实测 / B 静态核对 / C 人工审读）？是否存在以 B/C 级冒充 A 级、或未标注"未经实测"的情况？
7. 修改的副作用（每轮修改后必查）：本轮修复是否可能破坏此前已验证的部分？受影响的环节是否重新验证过？
8. 视角独立性：批判者与生成者是否共享同一上下文与偏差？关键分歧是否引入了第二种独立视角裁决？

## 科研写作 / 文献综述

1. 每条文献引注是否确实支撑对应的论断？是否存在只读了摘要却断言全文结论的情况？
2. 是否有编造或凭记忆补全的标题、DOI、数据？
3. 文献覆盖是否存在明显缺口（关键方向、近年进展、相反结论的研究）？
4. 论证链条：背景 → 现状 → 问题 → 方法 → 预期，逻辑是否完整，"然而"之后的转折是否成立？
5. 确定性措辞是否与证据强度匹配（初步表明 / 表明 / 证实）？
6. 是否混淆了文献报道的结论与自己的推断？
7. 高风险事实断言（数值、引文、结论性表述）是否经过独立检索或复算的一致性核对？未核对的是否已声明？

## 数据分析

1. 数据读取是否正确（编码、表头、单位、缺失值处理）？抽样核对过原始记录吗？
2. 统计方法的前提假设（分布、独立性、样本量）是否满足？
3. 结果能否被独立复算复现？随机过程是否固定了种子？
4. 图表坐标、标签、单位是否准确，有无误导性截断？
5. 是否存在选择性报告（只展示有利结果）？
6. 结论是否超出了数据实际支持的范围？

## 编程 / 工程

1. 测试是否真实运行并通过，还是只读了代码"认为"能跑？
2. 测试是否覆盖关键路径与边界条件，还是只测了顺利路径？
3. 错误处理：是否吞掉异常、忽略非零退出码？
4. 是否引入了需求之外的改动或未声明的依赖？
5. 破坏性操作（删除、覆盖、写库）是否有备份或可恢复手段？
6. 配置中的路径、密钥、环境假设是否会在目标机器上失效？
7. 回归：本轮改动后既有测试是否全部重跑通过？修复是否引入了新的告警或弃用用法？

## 使用说明

- 每轮审查至少产出一条具体批评意见；若全部通过，须明确写出"逐项检查未发现新问题"及检查了哪些项，防止反驳流于形式。
- 每条批评意见必须先引用原始验证信号（命令输出、测试结果、检索记录），再给出诊断；禁止无信号锚定的自由归因。
- 连续两轮无新增有效批评意见时，可判定自审收敛，将剩余风险如实告知用户。
